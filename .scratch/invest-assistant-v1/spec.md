## 1. 做什么，不做什么

做：

1. 从 J-Quants（Light 套餐）抓取东证全部证券的日线行情、上市名册、交易日历和 TOPIX，存进 6 张 SQLite 表；
2. 用两种借鉴 TradingView / QuantConnect 的技术策略，每个交易日收盘后给出信号；
3. 模拟账户按信号在下一交易日开盘模拟成交，从过去的起始日一路推进到今天（回测），之后随每日同步继续推进（模拟交易）。
4. 从已有 `technical_rating_v1` 账户复制初始配置，手选区间运行一组阈值并在页面查看结果（04b-A）；随后按市场形势提取区间批量运行（04b-B）。普通账户的两种策略继续保留。
5. 模型实验（06a，§7.7）：登记一份冻结契约，按日期折滚动训练模型，只用折外分数，经按分数持仓的策略和模拟账户的逐日交易规则回放成完整的买持卖、订单、成交和净值，并和规则基线、TOPIX、合格池等权一起出报告。06a 的 Ridge 只用来证明框架能跑通，不算一个候选策略。

不做：生产行情的全局点时版本管理、原始响应存档、财务 point-in-time 因子、Qlib、分红、融资融券、做空、盘中数据、实盘下单、登录。机器学习只在模型实验里训练和打分；模拟账户仍然只用固定规则的策略，模型不自动晋级成账户，也不自动调参（搜索预算固定为 1）；不导入 Qlib、FinRL 等外部框架的回测净值当作本项目结果。研究和模型实验保存输入指纹、配置及结果，不要求永久行情快照（ADR-0005、ADR-0007）。04b 不自动选冠军参数、按场景切换阈值或强制三阶段时间切分。

规则：

- 只有行情数据模块读写 `instruments`、`segment_periods`、`daily_bars`、`trading_calendar`；别的模块只调用它的读取函数，不写 SQL 访问这四张表。
- 只有模拟账户模块读写 `paper_accounts`、`paper_orders`。
- 指标模块和策略不碰数据库：输入是 DataFrame 和持仓事实，输出是信号。它们的测试只需要合成 K 线。
- 两个基线 seam 各有两个真实适配器（J-Quants：HTTP / 假数据；策略：两种策略）。04b 在账户模块内增加研究入口与观察/报告能力，按需要抽取共享逐日逻辑，不要求先引入特定 `SimulationEngine` interface。
- 研究配置、信号观察和模拟账本由账户模块独立保存；API 只提交任务或读取报告，不复制交易规则，也不直接调用内部账本/成交函数。
- 06a 增加第三个 seam：**训练器**（附录 A.6）。两个真实适配器 `ridge_v1` 和 `rule_short_reversal_v1`，测试里换成桩；换训练器不改日期折、回放和报告的代码。训练器和策略一样不碰数据库：输入是特征表和标签，输出是模型工件和分数。
- 只有模型实验模块读写 `model_experiment*` 六张表（§3.8）。它从账户模块只读两样东西：来源账户的初始资金、组合规则和费用，以及已看过截止日的账户和研究部分（`experiment_inputs`，§7.7），不直接查账户和研究的表，也不写它们。实验的回放经账户模块的整段回放 `replay_range`（附录 A.4），回读账本（每天计划了哪些单、开盘生效了什么、计划想要的持仓、期末数字）也经账户模块（`Replay.days()`、`end_state` 等），不另写一套交易规则，也不自己推算账本。

## 3. 数据模型（基线 6 张表，研究扩展另存）

金额与价格在 Python 中一律用 `Decimal`，在 SQLite 中存成文本；指标计算用 float（pandas）。日期存 ISO 文本 `YYYY-MM-DD`。

### 3.1 `instruments`

| 列 | 说明 |
|---|---|
| `code` PK | J-Quants 的 5 位代码（例如 `72030`、`130A0`）；TOPIX 为 `TOPIX` |
| `kind` | `stock` / `index` |
| `name`、`name_en` | 当前公司名 |
| `scale_category` | 当前规模分类（Core30 … Small 2、`-`） |
| `first_listed_seen`、`last_listed_seen` | 在名册中第一次、最后一次出现的交易日 |

### 3.2 `segment_periods`（市场分类区间）

| 列 | 说明 |
|---|---|
| `code`、`valid_from` PK | 区间起始交易日 |
| `valid_to` | 区间最后一个交易日；`NULL` 表示仍在持续 |
| `market_code` | `Mkt`（0111 Prime、0112 Standard、0113 Growth……） |
| `product_category` | `ProdCat`（011 国内股票……） |
| `sector33` | `S33` |

三项任一变化 → 关闭旧区间（`valid_to` = 前一交易日）并开新区间。某代码在当天名册中消失 → 关闭区间，不开新区间（退市）。

### 3.3 `daily_bars`（日线行情）

| 列 | 说明 |
|---|---|
| `code`、`date` PK | |
| `open`、`high`、`low`、`close` | 成交价格（J-Quants `O/H/L/C`），没成交为 `NULL` |
| `volume`、`turnover` | `Vo`、`Va`（日元） |
| `adjustment_factor` | `AdjFactor`，除权日以外为 1 |
| `ex_rights_type` | `ExRT`：1 拆股 / 2 合股 / 3 配股 / `NULL` |
| `upper_limit_hit`、`lower_limit_hit` | `UL`、`LL`：当天最高价触及涨停 / 最低价触及跌停 |
| `quality_status` | `ok` / `excluded` / `untradable`（见 4.4） |

不存 J-Quants 的 `Adj*` 列（ADR-0003）。TOPIX 也存这里，只有 OHLC。

### 3.4 `trading_calendar`

| 列 | 说明 |
|---|---|
| `date` PK | |
| `holiday_division` | `HolDiv`：0 休市、1 交易日、2 半日交易、3 休市但有节假日交易 |

开市日 = `holiday_division IN (1, 2)`。

### 3.5 `paper_accounts`（模拟账户）

| 列 | 说明 |
|---|---|
| `id` PK | |
| `name` | |
| `strategy` | `trend_pullback_v1` / `technical_rating_v1` |
| `strategy_params` | JSON，缺省项用策略默认值 |
| `portfolio_rules` | JSON：`initial_cash`（默认 10,000,000）、`max_positions`（10）、`max_weight`（0.10）、`cash_floor`（0.05）；可选 `max_adv20_fraction`（ADV20 上限，7.2 第 4 步）：没有这个键就是不设上限，现有账户都没有，新建账户页和 API 也不提供 |
| `costs` | JSON：`commission_rate`（0）、`commission_min`（0）、`slippage`（0.001，每边） |
| `start_date` | 起始交易日 |
| `advanced_through` | 已推进到的交易日；`NULL` 表示尚未推进 |
| `status` | `active` / `stopped`；`stopped` 不再随同步推进 |
| `backtest_data_mark` | JSON：回测追上最新交易日那一刻的 `daily_bars` 行数与最大日期（ADR-0001） |
| `created_at` | |

### 3.6 `paper_orders`（订单及账户事件）

| 列 | 说明 |
|---|---|
| `id` PK | |
| `account_id` | |
| `kind` | `buy` / `sell` / `split_adjustment` / `delisting_settlement` |
| `code` | |
| `signal_date` | 生成订单的交易日（账户事件为发生日） |
| `execution_date` | 计划成交的交易日（信号日的下一开市日） |
| `planned_quantity` | 计划股数（100 的整数倍） |
| `priority` | 生成时的候选排序值 |
| `reason` | JSON：处置、理由代码、关键指标值；买单被 ADV20 上限压缩时另有 `capped: "adv20"` |
| `status` | `pending` / `filled` / `expired` / `skipped` |
| `outcome_reason` | 过期或放弃的原因代码（见 7.3） |
| `filled_quantity` | 成交股数；拆合股调整为持仓股数的变化量（可为负） |
| `fill_price` | 含滑点的成交价 |
| `fees` | 手续费 |
| `cash_delta` | 本记录对现金的影响（买为负、卖为正、合股零股折现为正） |

**PaperAccount 的持仓、现金、净值都不单独存**：持仓 = 按时间累加已成交和已记账的记录；现金 = `initial_cash + Σ cash_delta`；每日净值 = 现金 + Σ 持仓股数 × 当日收盘成交价格（当天无收盘价则用最近一个）。研究另存观察值，不改变这份账户事实来源。

### 3.7 独立区间研究记录（04b-A、04b-B）

迁移 0005 新增 `manual_research_runs`、`manual_research_orders`，不复用／删除旧实装留下的 `research_*` 表。0004 是兼容已升级数据库的历史标记；全新库不建立旧研究表。

- runs：UUID、唯一 request_key、原请求、冻结来源配置及手选范围、retry_of、queued/running/completed/failed、创建／完成时间、逐日进度、错误、输入身份、代码身份和完成报告。
- orders：运行 ID + 局部序号，保存订单／成交／公司行动及费用；支持分页。来源账户 ID 仅作追溯，不级联删除研究。
- 完成报告保存每日 NAV／TOPIX 归一值／回撤、期末现金／持仓／挂单、收益差、成交数、费用及已实现／未实现盈亏；GET 不再访问生产行情重估旧结果。
- 配置修改／显式重试追加运行，已完成配置和报告不覆盖。A 不保存全合格池逐证券观察，也不提供账户状态分组。
- 输入 SHA256 覆盖含预热和流动性窗口的行情内容、TOPIX、全部历史分类／日历和后续调整系数；范围保守地含全股票，不仅成交股票。保存覆盖与行数用于解释，但指纹本身不是行情备份。代码身份为 app Python 源码及 uv.lock 的 SHA256。

04b-B：迁移 0006 新增 `research_batches`、`research_batch_segments`、`research_batch_attempts`，0007 新增 `regime_discoveries`、`regime_discovery_intervals`。

- regime_discoveries：UUID、唯一 request_key、请求、分类定义版本及完整定义、参数（搜索起止、趋势、波动）、queued/running/completed/failed、分类指纹、诊断、错误、代码身份、创建／完成时间。
- regime_discovery_intervals：发现 ID + 区间编号（1..N，从早到晚），保存**全部**候选区间的起止、开市日数、TOPIX 起止收盘及变化、RV20 范围、单日／短段／起点被截断／可能延续到搜索范围之后的标记，不论之后是否被选中。
- research_batches：UUID、唯一 request_key、请求、冻结的基础配置（不含区间）、discovery_id、选择记录（所选区间编号与候选总数）、提交时的分类指纹、代码身份、创建时间。
- research_batch_segments：批次 + 位置（从 1 起）、区间编号、起止日。research_batch_attempts：批次 + 位置 + 第几次尝试 → 一条 `manual_research_runs`；只有单段重试带客户端 request_key。
- 批次表不存状态：段的状态就是它最新一次尝试的研究运行状态，批次状态由各段推导（§7.6）。批次段的研究运行不出现在 A 的运行历史里，但可按 run_id 打开 A 的详情。

### 3.8 模型实验记录（06a）

迁移 0008 新增六张表，只由模型实验模块读写（§2）；都不对模拟账户和研究的表设外键，来源账户 ID 只写在冻结契约里作追溯。规则见 §7.7。

| 表 | 主键 | 内容 |
|---|---|---|
| `model_experiments` | `id`（UUID） | 唯一 `request_key`、原请求、冻结契约及其 hash、`retry_of`、queued/running/completed/failed、创建／完成时间、进度、研究输入指纹、读取记录（`data_read`，§7.7）、代码身份、错误和失败种类（`error_code`）、证据状态（给历史列表用）、完成报告 |
| `model_experiment_folds` | 实验、`model`、折号 | `model` 是 `model`（主模型）或 `baseline_1`、`baseline_2`……；训练起止、测试起止、训练样本数、耗时、模型工件（JSON）及其 hash；失败的折没有工件，记失败原因 |
| `model_experiment_scores` | 实验、`model`、`as_of` | 只存决策日的折外分数：所在折、打分的工件 hash、`{代码: 分数}`；某折失败，它的决策日没有这一行 |
| `model_experiment_replays` | 实验、`position` | 第几个回放（从 1 起，主模型基础成本在前）、哪个模型、`base`／`stress`、成本，结果：每日净值（含现金）、期末持仓、末日挂单、警告、各项指标、逐折、逐年 |
| `model_experiment_orders` | 实验、`position`、序号 | 这个回放的账本记录，形状同研究运行的订单 |
| `model_experiment_days` | 实验、`position`、日期 | 逐日记录（§7.7）及是否决策日；每个回放都有，压力场景的也有 |

## 4. 行情数据模块

### 4.1 J-Quants 适配器

- V2 API，请求头 `x-api-key`，key 来自环境变量 `JQUANTS_API_KEY`。
- 用到的接口：`GET /markets/calendar`、`GET /equities/bars/daily?date=`、`GET /equities/bars/daily?code=&from=&to=`、`GET /equities/master?date=`、`GET /indices/bars/daily/topix?from=&to=`。
- 分页：响应带 `pagination_key` 时原样带上继续请求，直到没有。
- 限速：Light 每账户每分钟 60 次，按滑动窗口计算，被拒的请求也计数。请求之间至少间隔 1.1 秒。
- 429 不带 `Retry-After`：等待 120 秒后重试。超时、网络错误、5xx：指数退避（5 → 10 → 20 → 40 秒），最多 5 次。my-invest 的退避公式底数等于上限、每次都等 60 秒，不要照抄。
- 可以从 my-invest `backend/app/integrations/jquants.py` 复制后改写。

适配器的 interface 只暴露「按日期取日线 / 按代码取区间日线 / 按日期取名册 / 取日历 / 取 TOPIX 区间」，返回已解析的记录。测试用的假适配器读内存数据，并能模拟 429、空响应和分页。

### 4.2 同步流程

一次同步（每日同步和 5 年回填是同一个函数）：

1. 取交易日历，覆盖写入 `trading_calendar`。
2. 目标日期 = 库里股票日线的最大日期之后、到今天为止的所有开市日；库为空时从「今天往前 5 年」的第一个开市日开始。
3. 按日期从早到晚，每个日期：取当天全部日线（分页）与当天名册 → 在**一个事务**里覆盖写入 `daily_bars`、更新 `segment_periods` 和 `instruments` → 提交。
   - 某日期日线返回空：如果是今天，说明数据还没出，结束本次同步并报告「当天数据未出」；如果是过去的开市日，记警告后继续。
4. 取 TOPIX 覆盖同一日期范围，写入 `daily_bars`（代码 `TOPIX`）。
5. 拆合股核对（4.3）。
6. 把本次结果（日期范围、写入行数、警告）追加到 `var/jobs.jsonl`。

中断后直接重跑：已提交的日期会被重新覆盖一次，结果不变，所以不需要记录进度。

名册处理的附加规则：

- 代码在名册中消失后又重新出现 → 记警告「代码重新出现」，照常开新区间（Q30）。
- 名册的公司名、规模分类变化只覆盖 `instruments`，不开新区间。

### 4.3 研究价格与拆合股核对

对某证券，交易日 `d` 的研究价格：

```text
累计系数(d) = Π 调整系数(e)，e 取 d 之后（不含 d）的所有除权日
研究价格(d) = 成交价格(d) × 累计系数(d)
研究成交量(d) = 成交量(d) ÷ Π 调整系数(e)，只取除权类型为 1（拆股）或 2（合股）的 e
```

配股（类型 3）只调价格、不调成交量。实现前对照官方计算说明 <https://jpx-jquants.com/ja/spec/eq-bars-daily/adj>。研究价格在读取时计算，不落表。

拆合股核对：本次同步中出现调整系数 ≠ 1 的每只证券，用「按代码取区间日线」取它除权日前 60 个交易日，逐日比对 J-Quants 的 `AdjC` 与本地研究收盘价；相对误差超过 0.1% 或绝对误差超过 0.1 日元（J-Quants 只保留 1 位小数）就记警告。回填完成后，从 5 年内有除权的证券里抽 20 只做同样核对。

### 4.4 质量标记

写入时逐行判定，结果取最坏的一档：

| 条件 | 标记 |
|---|---|
| `close` 为空（包括全天无成交） | `untradable` |
| 任一价格 ≤ 0，或 `high < max(open, close)`、`low > min(open, close)`、`high < low` | `untradable` |
| 价格齐全但 `volume` 或 `turnover` 为空 | `excluded` |
| 其余 | `ok` |

`untradable` 的日线不参与股票池、不产生信号、不能成交。缺交易日（开市日却没有日线）、复权对不上这类要跨行才能看出的问题，只在数据页查询时现算（行内规则可参考 my-invest `backend/app/services/quality_rules.py`）。

### 4.5 读取

interface 见[附录 A](#附录-a模块-interface)。要点：一次查询取整批证券，不逐只查询；研究价格、质量过滤、日历对齐都在模块内部完成，调用方拿到的是已经对齐好的行情。市场分类区间和成交额门槛不外露，收在 `universe()` 后面。

## 5. 指标模块

纯函数。输入是一只证券的 `Series`，或「行是交易日、列是证券代码」的宽表 `DataFrame`（由 `MarketFrame.wide(列名)` 得到），输出同形状的指标；所有计算都按列进行，所以全股票池约 1,600 只证券一次调用就算完，不逐只循环。公式按 TradingView Pine 的内置函数实现，并在代码注释中标明对应的 `ta.*`：

- SMA、EMA（`ta.ema`）、Wilder RMA（`ta.rma`）：EMA 和 RMA 都以前 n 个值的简单平均为起点，之前为 NaN——参考手册 `ta.ema` 的示例代码以第一个值为起点，但与 TradingView 实际数值比对，内置函数用的是简单平均（[indicators.md](indicators.md) §5 第 1 条）；每一列按它自己的前 n 个有效值计算（新上市的证券前面是 NaN）；
- RSI（RMA 平滑）、ATR（RMA 平滑的 True Range）、+DI / −DI / ADX（`ta.dmi`）；
- Hull MA、VWMA、一目均衡表（9/26/52）、Stochastic（14,3,3）、CCI（20）、Awesome Oscillator、Momentum（10）、MACD（12,26,9）、Stochastic RSI（3,3,14,14）、Williams %R（14）、Bull Bear Power（13）、Ultimate Oscillator（7,14,28）。

逐项公式、参数与取整见 [indicators.md](indicators.md)。

分母为零时的结果要显式规定并写进测试，不依赖 pandas 默认行为：RSI 平均损失为 0 时取 100、否则平均收益为 0 时取 0，DMI 的 `+DI + −DI` 为 0 时按 1 算（都照 Pine 手册示例）；其余指标（Stochastic、Stoch RSI、Williams %R 的最高等于最低，CCI 的平均偏差为 0，VWMA 的成交量全为 0，UO 的 True Range 之和为 0）结果为 NaN，之后含 NaN 的比较一律不成立。

NaN 的处理也要显式规定并写进测试：宽表对齐后，某证券当天没有日线的格子和停牌日一样是 NaN。规则是**把这一天当作没有 K 线**——TradingView 在无成交的日子本来就没有 K 线：递推类指标（EMA、RMA 及由它们组成的指标）跳过这一天、保留之前的平滑状态；窗口类指标（SMA、N 日最高价等）的「最近 n 根」跳过这一天往前数；这一天本身输出 NaN。停牌不多，实现上可以只对中间有 NaN 的列单独处理。

指标是因果的：某一天的值只用到这一天及以前的数据。递推类指标的值取决于输入从哪天开始（见 6.2「frame 的起点」）。

## 6. 信号

### 6.1 股票池

股票池按策略声明的**股票池规则**取（6.2、附录 A.3）。交易日 `t` 的股票池 = 同时满足：

- 是规则给出的候选证券，现有两种规则：
  - **Prime 普通股**（默认值，个股策略都用它：两个原有策略、05 的三个候选（6.6）和模型实验的按分数持仓（6.7））：`t` 所在的市场分类区间是 `market_code = 0111`（Prime）且 `product_category = 011`；
  - **TOPIX ETF**（TOPIX ETF 策略用它，6.5）：只有 1306（代码 13060），且 `t` 在上市名册中，即有覆盖 `t` 的市场分类区间（1306 的市场区分是 0109 その他，商品类别 014）；
- 最近 20 个开市日（含 `t`）的成交额平均 ≥ 5 亿日元，缺失或 `untradable` 的日子按 0 计；
- `t` 的日线不是 `untradable`。

两种规则只在「候选证券从哪里来」上不同，后两条共用同一段计算。股票池只决定能否**新开仓**；已持仓证券离开股票池不会被卖出，仍由策略的退出规则管理（Q26）。

### 6.2 策略 seam

策略是一个声明了名称、默认参数、预热期、图上画哪些指标、股票池规则（在哪套股票池里新开仓，6.1）和参照行情（读取但不交易的行情代码，见下）的对象，只有一个方法 `evaluate(frame, day, holdings)`（[附录 A](#附录-a模块-interface)）。`frame` 里每只**能判断**的证券（预热期够、当天不是 `untradable`）都得到一条信号，处置可以是「不参与」，信号里带着这一天的指标值。它对两类证券给出信号：

- **未持仓**：从空仓角度判断「可持有」还是「不参与」，给出理由；「可持有」的带候选排序值。`holdings` 传空时，其中「可持有」的就是信号页的入场候选，与任何账户无关。
- **持仓**：结合持仓事实判断「可持有」还是「必须清仓」，给出理由。持仓只传代码、股数和开仓成交日；持有天数和开仓以来最高研究收盘价由策略自己从行情算出，不由调用方传入——否则这条规则会散到每个调用方去。
  - 持有天数 = `frame` 里这只证券从开仓成交日到 `day`（含两端）的日线条数：停牌日库里有一条 `untradable` 日线，算一天；完全没有日线的开市日不算。
  - `frame` 里这只证券的日线晚于开仓成交日才开始时，直接报错，不静默计算——否则开仓以来最高收盘价会被算低，跟踪止损无声地算错。

返回「不参与」也是为了证券详情页：按日循环调用 `evaluate`，就同时得到指标曲线（每天信号里的指标值）和历史入场点，不需要为画图另加方法。

策略不查数据库、不筛股票池：`frame` 里有什么就评价什么，股票池由调用方按策略声明的股票池规则先问行情数据模块。预热期不足的证券没有信号；持仓证券当天 `untradable`（例如停牌）时也没有信号，持仓维持原状。

**参照行情**（CONTEXT.md）：策略读取、但永远不交易的行情代码，默认为空。两个个股策略和一直持有对照组不声明；TOPIX 均线和 TOPIX 动量声明 TOPIX（6.5）。

- 调用方把它加进读取范围：信号页读「股票池 ∪ 参照行情」，证券详情页读「该证券 ∪ 参照行情」，模拟账户推进一次读「整段股票池的并集 ∪ 持仓 ∪ 挂单 ∪ 参照行情」，研究运行读「整段股票池的并集 ∪ 参照行情」。「要评价的代码 ∪ 参照行情」只写在一个函数里（`codes_to_read`，附录 A.3），这些调用方都用它。入场候选仍然只取当天股票池里的；建账户时的预热期校验不变，仍按 TOPIX 的开市日数计（7.1）。
- `evaluate` 把参照行情的代码只当作输入，永远不给它信号；`frame` 里其余每只能判断的证券照常得到一条信号。所以在任何证券的详情页选 TOPIX 均线或 TOPIX 动量都画得出线，但只有股票池里的证券会成为入场候选。证券详情页也只在股票池点名的代码（1306）上标入场点；在其他证券上照样画线，但不标入场点，并写明这个策略只交易 1306。
- 规则只读参照行情的策略共用一个基类（`ReferenceSeriesStrategy`，规则写在 `judge_on_reference(readings, held)` 里，和个股策略基类的 `judge(readings, position)` 区分开；两个基类共用按 `frame` 缓存和按日取值的那一段）：对整个 `frame` 用参照行情算一次线，当天参照行情有收盘、而且收盘个数（含当天）够预热期时，其余每只当天有日线且不是 `untradable` 的证券都按同一组指标值得到信号；否则当天谁都没有信号。算线时拿到的是参照行情在 `frame` 全部日期上的收盘，所以也看得出哪天是每月第一个开市日（TOPIX 动量的判断日）。

**frame 的起点**：递推类指标的值取决于输入从哪天开始。策略对整个 `frame` 把指标算一次，按 `frame` 对象缓存（缓存不属于 interface），之后每次 `evaluate` 只按日取值，所以按日循环调用的开销与只调用一次相近。代价是：同一证券同一交易日，`frame` 起点不同，指标值会略有不同（见第 12 节）。调用方至少要从第一个评价日往前读预热期那么多个开市日；`frame` 传入后不得再修改。一条测试守住「不看未来」：用整个 `frame` 在 `t` 日评价，结果等于把 `frame` 截到 `t` 日再评价。

「往前读多少、先取股票池、再补上证券名称」这套组装只写在一处：`strategies` 模块的 `entry_candidates` 和 `history`（附录 A.3），信号页和证券详情页的 API 只调用它们。

### 6.3 Trend-Pullback v1

照搬 my-invest `docs/design/daily-investment-timing.md` §5，所有数字都是可覆盖的参数。预热期 180 个交易日（EMA60 的 3 倍）。

入场（`t` 日收盘全部成立）：

```text
EMA20[t] > EMA60[t]  且  close[t] > EMA60[t]
+DI14[t] > −DI14[t]  且  ADX14[t] > 20  且  ADX14[t] ≥ ADX14[t−1]
RSI14[t−1] ≤ 30      且  RSI14[t] > 30
排序值 = ADX14[t] / 100
```

持仓退出（任一成立即「必须清仓」，理由按以下优先级取第一个）：

1. 跟踪止损：`close[t] ≤ 开仓以来最高收盘 − 2 × ATR14[t]`；
2. 趋势失效：`EMA20[t] ≤ EMA60[t]` 或 `+DI14[t] ≤ −DI14[t]`；
3. 超买回落：`RSI14[t] ≥ 70` 且 `RSI14[t] < RSI14[t−1]`；
4. 时间退出：已持有 5 个交易日（开仓成交日收盘算第 1 天）。

退出当天不重新入场。以上价格都用研究价格。

**已知问题**：按这组规则，02 回填的三年数据上一次都不会入场——RSI14 ≤ 30 与「趋势完好」几乎不会同一天成立。失败记录与 v2 的方向见[策略研究](strategy-research.md) §2；v1 保留原样，作为系统中「没有交易」这条路径的检验对象。

### 6.4 技术评级 v1

按 TradingView `TechnicalRating` 库 v3 的 Pine 源码复刻 26 项——内置「Technical Ratings」指标、筛选器和个股页仪表盘用的都是它；源码存在 [tradingview/](tradingview/) 下，逐项规则见 [indicators.md](indicators.md) §4：

- 均线组 15 项：SMA、EMA 各取 10/20/30/50/100/200，Hull MA 9，VWMA 20，一目均衡表；
- 振荡器组 11 项：RSI 14、Stochastic 14,3,3、CCI 20、ADX 14、AO、Momentum 10、MACD 12,26,9、Stoch RSI 3,3,14,14、Williams %R 14、Bull Bear Power 13、UO 7,14,28。

每项给出 −1/0/+1；当天算不出的项不计入平均。组内取平均，总评是两组的平均（各占 50%）。官方说明页 <https://www.tradingview.com/support/solutions/43000614331-technical-ratings/> 的文字与源码有一处不一致（ADX 的卖出条件），按源码。五档：`> 0.5` 强烈买入、`(0.1, 0.5]` 买入、`[−0.1, 0.1]` 中性、`[−0.5, −0.1)` 卖出、`< −0.5` 强烈卖出。

- 入场：总评 > `entry_above`（默认 0.5）；排序值 = 总评。
- 持仓退出：总评 < `exit_below`（默认 −0.1）。04b 两个阈值均允许 −1 到 +1，拒绝非有限数字和越界值；评分五档定义不随交易阈值改变。
- 预热期 260 个交易日。长周期 EMA 的数值会因起算点不同与 TradingView 页面略有差异，属于已知局限。

### 6.5 TOPIX ETF 策略

规则见 [TOPIX ETF 策略规格](../topix-etf-strategies/spec.md)，冻结，改规则就是新版本。它们的股票池规则是 TOPIX ETF（6.1），所以只交易 1306（NEXT FUNDS TOPIX 連動型上場投信，代码 13060）；成交、费用、拆合股调整和估值与个股策略完全相同，ETF 分配金不入账（第 12 节）。新建账户页为它们建议的组合规则是最多 1 只、单只上限 100%、现金下限 5%，也就是约 95% 的资金买入 1306，用户仍可修改；建账户接口不强制。

- **一直持有 v1**（`topix_buy_and_hold_v1`，对照组）：参数只有 `warmup_sessions`，默认 1（当天的日线），小于 1 时拒绝。1306 当天能判断（有日线且不是 `untradable`）就是「可持有」：空仓时理由 `always_hold`、排序值 1；持仓时同样可持有，永不清仓。不画线。账户因此在起始日收盘出信号、下一开市日开盘买入一次，之后一直持有；和按 TOPIX 趋势进出的策略比较时，成交、滑点、拆股、不含分配金这几点口径一致。
- **TOPIX 均线 v1**（`topix_ma_v1`）：参照行情是 TOPIX（6.2）。参数 `ma_sessions` 默认 200，`band` 默认 0.01（比例，即 1%），`warmup_sessions` 默认 200；预热期比 `ma_sessions` 小、均线窗口不是至少 1 的整数、缓冲带为负，都拒绝建策略。每个开市日收盘判断：
  - 均线 = 含当天在内最近 `ma_sessions` 个 TOPIX 收盘的简单平均，窗口按 TOPIX 有收盘的开市日往前数（第 5 节）；偏离 = TOPIX 收盘 ÷ 均线 − 1。
  - 空仓时：收盘高于均线 ×（1 + `band`）为「可持有」，理由 `topix_above_ma`，排序值 = 偏离；否则「不参与」，理由 `topix_below_ma`（收盘低于均线 ×（1 − `band`））或 `topix_near_ma`（在缓冲带内）。
  - 持仓时：收盘低于均线 ×（1 − `band`）为「必须清仓」，理由 `topix_below_ma`；否则「可持有」。
  - 落在缓冲带内（含恰好在门槛上）不改变状态。门槛按「均线 ×（1 ± `band`）」和收盘比，而不是先算偏离再和 `band` 比：两者在数学上相同，但浮点下 101 ÷ 100 − 1 比 0.01 大一点点，恰好 1% 的收盘会被当成越过门槛。`band` = 0 时退化为「高于均线就买、低于均线就卖」。
  - 当天 TOPIX 没有收盘、TOPIX 的收盘个数不够预热期，或 1306 当天不可交易时，没有信号。
  - 指标值含 `topix_close`、`topix_ma`、`deviation`；在单独一栏画 TOPIX 收盘和均线，证券详情页标出空仓时会买入的日期。
  - 这些是策略自己的规则，不是市场形势：不读、不复用 `topix_trend_vol_v1` 的标签。
- **TOPIX 动量 v1**（`topix_momentum_v1`）：参照行情是 TOPIX（6.2）。参数 `lookback_sessions` 默认 252（约 12 个月），`warmup_sessions` 默认 253（回看长度加当天）；预热期少于 `lookback_sessions` + 1、回看长度不是至少 1 的整数，都拒绝建策略。只在每月第一个开市日收盘判断：
  - 过去收益 = TOPIX 当天收盘 ÷ `lookback_sessions` 个开市日前的收盘 − 1，只数 TOPIX 有收盘的开市日（第 5 节）。每个开市日都算，不是判断日也一样。不扣无风险利率：样本期日本短期利率接近 0。
  - **判断日**：当月第一个开市日。判法：`frame` 里当天之前最近一个有行情的日期在上个月或更早。`frame` 里的日期就是开市日，所以月初逢休市（例如 1 月 1–3 日）时，当月第一个开市日才是判断日。判断日当天 TOPIX 没有收盘时没有信号，下一个开市日也不算判断日：本月不判断，状态保持到下个月的判断日。判断频率属于规则本身，不是参数，改成每天判断就是新版本。月中建的账户要等到下个月第一个开市日才可能买入。
  - 判断日，空仓时：过去收益为正为「可持有」，理由 `topix_momentum_up`，排序值 = 过去收益；否则「不参与」，理由 `topix_momentum_down`（为负）或 `topix_momentum_flat`（恰好为 0）。
  - 判断日，持仓时：过去收益为负为「必须清仓」，理由 `topix_momentum_down`；否则「可持有」。恰好为 0 时不改变状态。
  - 不是判断日时：空仓「不参与」，理由 `not_check_day`；持仓「可持有」。过去收益是正是负都一样，月中不买也不卖。
  - 正负按「当天收盘和回看起点的收盘谁大」来定，不先算过去收益再和 0 比，和均线的门槛同一个道理。
  - 当天 TOPIX 没有收盘、TOPIX 的收盘个数不够预热期，或 1306 当天不可交易时，没有信号。
  - 指标值含 `topix_close`、`lookback_close`（回看起点的收盘）、`past_return`、`check_day`（判断日为 1，否则为 0）；在单独一栏画过去收益（每天都画），证券详情页标出空仓时会买入的日期，这些日期只会落在判断日。
  - 改成按月判断之前，在全样本上数过进出次数（没有看收益），见 TOPIX ETF 策略规格「补充说明 · 进出次数检查」；以后把它放进 05 的研究流程时要如实披露。
  - 这些是策略自己的规则，不是市场形势：不读、不复用 `topix_trend_vol_v1` 的标签。

**和市场形势的关系**：这些策略的持有期和 `topix_trend_vol_v1` 的「上涨」形势高度重合——都看 TOPIX 自己的趋势，持有的日子大多正是上涨形势的日子。所以按市场形势分组看它们的结果几乎没有信息量，不能当作「这个策略适合哪种形势」的证据。例如 2025-09-30 至 2026-09-29 这一年每天都是上涨形势，均线策略整年持有，和一直持有没有区别；以后把它们放进 05 的研究流程，盲测期也分不出它们和对照组。

信号页从空仓角度给入场候选（6.2），所以 TOPIX 策略没有候选时写的是「空仓的话，今天收盘后不会买入 1306」，而不是「不持有」：已持有 1306 的账户这一天可能继续持有（动量的非判断日、均线的缓冲带内）。

### 6.6 05 候选策略

ticket [05](issues/05-three-ohclv-strategy-candidates.md) 的三类候选，只实现了策略本身：能在新建账户页选择、逐日推进，和其他个股策略同一套成交与组合规则。05 的研究流程（开发、验证、盲测分阶段，版本谱系，成本与容量情景，晋级门槛）都还没有实现，所以这些账户的结果不是 05 意义上的样本外证据，页面说明里写明「尚未通过研究验证」。ticket 05 原本要求通过门槛前不接入模拟账户，这里按用户的决定放开（2026-10-06）。

三个策略的股票池规则都是 Prime 普通股，新建账户页建议的组合规则和其他个股策略一样（最多 10 只、单只上限 10%、现金下限 5%）。名字不写死窗口长度，ticket 05 里的预注册变体就是改参数（见各条）。只用研究价格，信号在 `t` 收盘给出，`t+1` 开盘成交。

- **长趋势 v1**（`long_trend_v1`，05 A 的主版本）：参数 `sma_sessions` 默认 200，`warmup_sessions` 默认 200；预热期比均线窗口小、均线窗口不是至少 1 的整数，都拒绝建策略。只在每月第一个开市日（判断日，判法同 TOPIX 动量，6.5）收盘判断：
  - 均线 = 这只股票含当天在内最近 `sma_sessions` 根日线研究收盘的简单平均，只数它有日线的开市日；偏离 = 收盘 ÷ 均线 − 1。
  - 判断日，空仓：收盘高于均线为「可持有」，理由 `above_sma`，排序值 = 偏离；否则「不参与」，理由 `not_above_sma`。
  - 判断日，持仓：收盘不在均线之上（含恰好等于）为「必须清仓」，理由 `not_above_sma`；否则「可持有」。
  - 非判断日：空仓「不参与」（`not_check_day`），持仓「可持有」。
  - 持仓不参与排名：只要还在均线之上就留着，不管别的股票偏离更大。
  - 指标值含 `close`、`sma`、`deviation`、`check_day`；在价格图上画均线。
  - ticket 05 的判断日是月末，这里沿用 TOPIX 动量的「每月第一个开市日」：策略只看得到 `frame` 里截至当天的日期，判断不了明天是不是下个月，月初判断不需要预知日历。两者只差一个开市日。
  - 预注册变体 `absolute_momentum_12m_v1`（过去 12 个月收益为正才持有）规则不同，没有实现。
- **短期反转 v1**（`short_reversal_v1`，05 B）：参数 `return_sessions` 默认 5，`max_holding_sessions` 默认 5，`warmup_sessions` 默认 6；预热期少于 `return_sessions` + 1、两个窗口不是至少 1 的整数，都拒绝建策略。每个开市日收盘判断：
  - 过去收益 = 收盘 ÷ `return_sessions` 根日线前的收盘 − 1，只数这只股票有日线的开市日。
  - 空仓：收盘低于回看起点的收盘（跌了）为「可持有」，理由 `short_term_drop`，排序值 = −过去收益（跌得越多越靠前）；否则「不参与」，理由 `no_short_term_drop`。
  - 持仓：已持有 `max_holding_sessions` 个交易日（开仓成交日算第 1 天）为「必须清仓」，理由 `time_exit`，不管期间涨跌；否则「可持有」。
  - ticket 05 的「事先固定的弱势分位」在这里是「下跌的股票里，按跌幅排进空位的那几只」：策略看不到当天的股票池，算不出分位；组合规则在当天股票池里按排序值取前「空位」个（7.2），效果就是跌得最多的那几只。流动性过滤用股票池本身的 20 日平均成交额 ≥ 5 亿日元（6.1）。
  - 预注册变体 `short_reversal_20d_v1` = `return_sessions` 20、`max_holding_sessions` 10、`warmup_sessions` 21。
  - 指标值含 `close`、`lookback_close`、`past_return`；单独一栏画过去收益。
- **横截面动量 v1**（`cross_sectional_momentum_v1`，05 C）：参数 `momentum_sessions` 默认 126，`skip_sessions` 默认 21，`warmup_sessions` 默认 127；预热期少于 `momentum_sessions` + 1、回看长度不是至少 1 的整数、跳过数不是 0 到回看长度之间（不含回看长度）的整数，都拒绝建策略。只在每月第一个开市日收盘判断：
  - 动量 = `skip_sessions` 根日线前的收盘 ÷ `momentum_sessions` 根日线前的收盘 − 1，只数这只股票有日线的开市日；`skip_sessions` = 0 时到当天收盘为止。默认值就是「6-1」：过去 6 个月，去掉最近 1 个月（最近一个月的走势倾向于回落，见 05 B）。
  - 判断日：每只能判断的股票，持仓与否，都是「可持有」，理由 `momentum_rank`，排序值 = 动量。排名看的是股票之间的先后，动量为负也可能排在前面。
  - 非判断日：空仓「不参与」（`not_check_day`），持仓「可持有」，不带排序值。
  - 它声明**持仓参与排名**（`ranks_holdings`）：判断日由组合规则在当天股票池里取排名最前的 `max_positions` 只，持仓跌出这份名单就卖出（7.2）。只换进换出，留下的持仓不加不减，不调回等权。
  - 预注册变体 `cross_sectional_momentum_12_1_v1` = `momentum_sessions` 252、`warmup_sessions` 253。
  - 指标值含 `close`、`from_close`、`to_close`、`momentum`、`check_day`；单独一栏画动量（每天都画）。

### 6.7 按分数持仓（06a）

**按分数持仓 v1**（`score_top_n_v1`）是模型实验把模型分数变成买持卖的策略：决策日持有分数最高的那几只，持仓也参与排名。分数和决策日由调用方放在一张分数表里交给它，所以它不进策略注册表，不出现在新建账户页、信号页和证券详情页，只由模型实验（以及测试里的模拟账户）直接构造。规则表、参数和理由码见 §7.7。模型的分数本身不是策略：同一张分数表换一套持有规则，就是另一个策略版本。

## 7. 模拟账户

### 7.1 推进一个交易日 `t`

对一个账户，严格按以下顺序：

1. **拆合股调整**：持仓证券在 `t` 除权（类型 1 或 2）→ 持仓股数 ÷ 调整系数（由成交记录推出的成本价随之 × 调整系数），记一条 `split_adjustment`；合股后不足 1 股的部分折成现金，金额 = 不足 1 股的新股数 × `t` 前一交易日收盘成交价格 × 调整系数。同一证券 `t` 日待成交的订单按同样比例调整股数：卖单改为全部新持仓，买单向下取整到 100 股（为 0 则放弃）。配股（类型 3）不调整持仓，记警告。
2. **退市结清**：持仓证券在 `t` 的名册中消失 → 按它最后一个收盘成交价格结清，记一条 `delisting_settlement`；它的待成交订单改为 `expired`（原因 `delisted`）。
3. **开盘成交**：执行日为 `t` 的待成交订单，先卖后买，买单按排序值从高到低（7.3）。
4. **重下卖单**：`t` 开盘过期的卖单，在 `t` 收盘重新下一张同样的卖单（执行日为下一开市日），直到成交或退市结清——不需要策略再次给出信号（Q26）。
5. **收盘出信号并生成订单**（7.2）。
6. `advanced_through = t`。

每个交易日在**一个事务**里提交：这一天写下的全部记录和 `advanced_through = t` 一起提交或一起放弃，所以推进中途被打断，重跑会从断点接着推进，不会多写或漏写一天。同一账户、同一份数据推进两次，得到逐行相同的记录：记录里不写墙上时间，金额全用 `Decimal`，同分按代码排序。

PaperAccount 从 `start_date` 逐日推进到最新交易日，追上后写 `backtest_data_mark`，之后每次同步成功继续推进新的交易日。研究运行使用复制的账户配置、同批一致的行情输入和独立账本，复用本节的交易规则，不随行情同步继续推进（ADR-0006）。已成交的 paper account 记录不因生产日线后来被修正而改写。

新建账户时校验：`start_date` 必须是开市日，且之前至少有该策略预热期那么多个开市日的数据。具体数法：数 TOPIX 的日线（它和股票按同样的日期同步，只读一个代码），从交易日历的第一天数到 `start_date` 的前一天，要不少于 `warmup_sessions`。有两点要注意，都是现有行为、没有改：

- 起始日当天不算，所以比规则本身多要一个开市日。策略的预热期含当天：TOPIX 动量默认 253，规则要的是起始日当天及之前共 253 个收盘，建账户却要起始日之前就有 253 个。
- 从日历的第一天数，不是从 TOPIX 的第一根日线数。真实库的日历从 2021-10-04 开始，TOPIX 的日线从 2021-09-24 开始，前面这 6 个开市日不算。所以按默认预热期，三个 TOPIX ETF 策略最早的共同起始日是 2022-10-17（TOPIX ETF 策略规格「补充说明 · 最早起始日」）。

### 7.2 组合规则：从信号到订单

在 `t` 收盘：

1. 持仓中得到「必须清仓」的 → 卖单，股数为全部持仓。已在 7.1 第 4 步重下卖单的持仓不再评价。
   - 策略声明**持仓参与排名**（`ranks_holdings`，现在有横截面动量（6.6）和按分数持仓（6.7））时：当天得到带排序值的「可持有」的持仓，和候选一起按排序值降序、代码升序排名，争夺其余持仓（没有排名的，例如当天停牌）留下的位置；排在位置之外的持仓 → 卖单，股数为全部持仓，理由 `ranked_out`。候选只保留排进位置的。
2. 空位 = `max_positions` − （持仓数 − 本次卖出数）。
3. 候选 = 入场评价「可持有」且未持仓的证券，按排序值降序、代码升序，取前「空位」个。
4. 每只候选的目标金额 = `t` 收盘净值 × `min(max_weight, (1 − cash_floor) / max_positions)`；计划股数 = ⌊目标金额 ÷ `t` 收盘成交价格 ÷ 100⌋ × 100。
   - **ADV20 上限**（可选，组合规则的 `max_adv20_fraction`）：设了上限、计划股数大于 0 时，计划股数再取它和 ⌊上限 × ADV20 ÷ `t` 收盘成交价格 ÷ 100⌋ × 100 中较小的一个。ADV20 = 含 `t` 在内最近 20 个开市日成交额的平均（日元），没有日线或 `untradable` 的日子按 0 计，口径同股票池的流动性条件（6.1）；查不到 ADV20 的按 0 计。被压缩的买单在理由里记 `capped: "adv20"`，压成 0 的记为 `skipped`（原因 `adv20_cap`）。没有这个键就不设上限：现有模拟账户和研究运行都不设，模型实验默认 5%（§7.7）。上限只在计划时按 `t` 收盘价算，开盘按开盘价成交，所以成交金额可能略超上限。
5. 预算 = 当前现金 + 本次卖单按 `t` 收盘价估算的所得 − `cash_floor` × 净值。按顺序分配，超出预算的候选记为 `skipped`（原因 `insufficient_cash`）；计划股数为 0 的记为 `skipped`（原因 `lot_unaffordable`，按目标金额本来就买不起一手的，不看 ADV20 上限）。被 ADV20 上限压缩后的股数照样过这一步的预算检查。
6. 开仓后不调仓、不加仓；持仓股数只因卖出、拆合股调整和退市结清而变化。

### 7.3 开盘成交规则

对执行日为 `t` 的每张订单，用 `t` 的成交价格：

| 情形 | 结果 |
|---|---|
| `t` 日线为 `untradable` 或 `open` 为空 | `expired`，原因 `untradable` |
| 卖单，`lower_limit_hit` 且 `open = low` | `expired`，原因 `limit_down_open` |
| 买单，`upper_limit_hit` 且 `open = high` | `expired`，原因 `limit_up_open` |
| 卖单，其余 | 全部成交，价 = `open × (1 − slippage)` |
| 买单，其余 | 价 = `open × (1 + slippage)`；股数 = min(计划股数, 可用现金扣除手续费后能买的整手数)；为 0 则 `expired`，原因 `insufficient_cash` |

- 手续费 = max(`commission_min`, 成交额 × `commission_rate`)，默认 0。
- 卖出所得在成交当时就计入可用现金，同一开盘后面的买单可以使用。
- 成交时不再检查 `cash_floor`，它只在生成订单时起作用。
- 不做部分成交；成交时不看成交量占比，成交额只在计划买单时可以按 ADV20 设上限（7.2 第 4 步，默认不设）；成交价不按呼值取整。

### 7.4 统计（读取时计算）

由逐日净值序列与成交记录计算：总收益、年化收益、最大回撤、夏普比率（日收益均值 ÷ 标准差 × √245，无风险利率 0）、胜率（已结束的持仓里扣除费用后盈利的比例）、平均持有交易日数、年化换手率（（买入成交额 + 卖出成交额）÷ 2 ÷ 平均净值，按年折算）、相对 TOPIX 的超额年化收益；净值曲线与 TOPIX 曲线在起始日归一为 1 后对比。报表注明「不含分红、不含税」。

### 7.5 指定区间策略回测（04b-A）

来源账户仅提供 technical_rating_v1 的初始资金、组合限制、费用和其他策略参数，用户手选 [s,e] 并指定 entry_above / exit_below（默认 0.5 / -0.1，有限数值且在 [-1,1]）。每次提交只跑一个配置。来源当前持仓、待单及已推进日期不进入研究。

s/e 都必须是已知开市日且 s≤e，TOPIX 需覆盖完整预热至结束日；全市场缺行情日明确报错，不静默改日期。为末日计划需要已知的下一开市日。每个区间相同初始资金、空仓、无挂单启动；预热只计算指标。s 收盘信号最早在下一开市日开盘成交，运行至 e 收盘估值，不强平或执行 e 之后的挂单。

研究与普通账户共用逐日交易函数及公司行动／组合／成交规则。区间内的逐日循环（空仓、无挂单、初始资金起步，每天 `replay_day`，收盘记净值点）写在账户模块的整段回放 `replay_range` 里（附录 A.4），研究运行和模型实验（§7.7）都用它；它给出的净值点带当天现金，研究运行存结果时不存现金这一项，结果和抽出之前逐位相同。报告展示 s 收盘到 e 收盘净收益、同范围 TOPIX 价格收益及差值、最大回撤、成交数、实际手续费、每日曲线、交易记录和期末未平仓情况。已实现盈亏为总货币盈亏减期末浮盈亏，包含实际已记账公司行动现金。单日／零成交明确说明，不用短段年化或 Sharpe 排名。不含分红、税；结果为探索性，不宣称策略泛化有效。

B 按 TOPIX 市场形势自动提取区间，逐段调用同一个独立回放（§7.6）。多阈值批量比较、全候选诊断和连续账户状态归因均延后，不是 A 的验收前置。不强制开发／验证／盲测三阶段，也不通过统计回归生成交易。

### 7.6 按市场形势选区间逐段回测（04b-B）

**分类定义 `topix_trend_vol_v1`**：固定的工程默认，不提供规则编辑器，改动即新版本；页面可查看公式。只用 TOPIX 收盘价和开市日历，与策略参数、成交历史无关。所有窗口按开市日计数（休市日不在窗口里）；缺失或不大于 0 的收盘是缺口，不补值。

- 趋势：MA200 = 含当日在内最近 200 个收盘的平均；偏离 = 收盘 ÷ MA200 − 1；斜率 = MA200 ÷ 20 个开市日前的 MA200 − 1（共需 220 个有效收盘）。偏离 > 1% 且斜率 > 0 为上涨；偏离 < −1% 且斜率 < 0 为下跌；其余为中性，只是震荡候选，不代表已确认横盘（等号、方向相反都算中性）。
- 波动：日收益 r = ln(当日收盘 ÷ 前一开市日收盘)；RV20 = 最近 20 个 r 的样本标准差（ddof=1）× √252；阈值 = 当日**之前** 252 个 RV20 的中位数，不含当日、不用全样本（共需 273 个有效收盘）。RV20 高于阈值为高波动，其余（含相等）为低波动。
- 窗口够不着历史开头记为「预热不足」，窗口里有缺口记为「数据缺口」（两者都有时算缺口），该维度未知；未知永远不匹配。只筛趋势时完全不看波动。某日的标签只用当天及以前的收盘，改动之后的价格不会改变它。

**区间发现**：用户给搜索起止、趋势（上涨／下跌／中性）和可选波动（高／低／不限）。异步任务从「首个搜索日往前 273 个开市日」读到搜索结束日，之后的日子一概不读；搜索结束日不能晚于已有 TOPIX 行情。搜索范围内满足条件的连续开市日组成最长的一段就是一个形势区间：休市日不打断，不满足条件或缺口的开市日打断；不合并、不剔除短段。每段标注开市日数、TOPIX 起止变化、RV20 范围，以及单日、短段（少于 20 个开市日，只作提示）、起点被截断（第一天就匹配且前一开市日也匹配）、可能延续到搜索范围之后（止于最后一个搜索日）。另存诊断：预热不足和缺口造成未知的日期段、缺口日、各趋势／波动的天数；零匹配也是正常完成。发现保存分类指纹 = 定义 + 所读每个开市日收盘的 SHA256；日常同步只追加搜索结束日之后的日子时它不变。

**研究批次**：提交引用 discovery_id 和区间编号，日期由服务端从这次发现取，不信任客户端；不属于该发现的编号拒绝并逐个列出，重复编号去掉，按编号排序。只接受一个来源账户和一组 entry_above／exit_below。单批上限 20 段，超出拒绝，不静默截断；任何一段不能运行（例如策略预热不足）就整批拒绝并逐段说明原因。提交时在任务锁内重算分类指纹，与发现时不同就拒绝（412），要求重新发现。批次在一个任务里逐段运行，锁一直持有到最后一段结束，所以同批各段读的是同一份数据。

- 每段的每次尝试都是一条普通研究运行（§7.5），用来源的初始资金空仓启动，不继承前一段的持仓或挂单；输入指纹、账本、净值各自保存。
- 段的状态 = 最新一次尝试的状态。批次状态：有段在运行为 running；否则有段排队为 queued；全部完成为 completed；部分完成为 partial；一段都没完成为 failed。某段失败不停止其他段；重启时未完成的段标为失败，已完成的不受影响。
- 失败段可以单独重试：追加新尝试、沿用冻结配置；回放前该段的研究输入指纹必须与之前的尝试相同，并同样重做分类指纹检查，否则拒绝并要求重新发现、新建批次。
- 结果分布只算已完成的段，每段等权，分母 = 已完成段数（失败段不当作 0）：收益和收益差的列表与中位数；盈利（收益 > 0）／持平／亏损段数，跑赢 TOPIX（收益差 > 0）／持平／落后段数，比例 = 计数 ÷ 分母；最差收益段、最差收益差段；日期覆盖。不拼接净值、不连乘各段收益、不合成总回撤。
- 各段长度不同、多个短段可能属于同一次行情；区间边界要事后才知道，这不是实时择时能力。TOPIX 为价格指数，不含分红、税；结果是探索性的。

### 7.7 模型实验（06a）

模型实验是一个后台任务：在一份冻结契约下，按日期折滚动训练模型，只用折外分数，经按分数持仓的策略（6.7）和本章的逐日交易规则回放成完整的买持卖、订单、成交和净值，同批跑规则基线，并和 TOPIX、合格池等权一起出报告。模型的分数本身不是策略，把分数变成买、持、卖、留现金的是按分数持仓的规则和组合规则。06a 的 Ridge 只证明框架能从数据一路走到净值和报告，不是候选策略。实验不建模拟账户、不改任何账户；结论最多是探索性的，06a 不出「通过」。

**冻结契约**。登记时由请求、默认值和可选的来源账户算出，校验通过后冻结，连同它的 hash（规范 JSON 的 SHA256）一起存下，之后不改。改任何一项（模型、参数、持有规则、成本、区间……）都要登记新实验；重试沿用原契约。

两个样本下限按真实数据定：默认契约在真实数据上要跑得过，太短的区间要拦得住。

- 每折训练样本 20,000：十个特征的线性模型本身用不了这么多样本，但同一天的证券高度相关，有效样本更接近训练天数。20,000 大约是 40 个开市日 × 500 只的 Prime 合格池。真实数据上默认契约最少的一折（第 1 折）有 101,891 个，过得去；训练窗设得太短，或者训练窗大半落在 Prime 市场 2022-04-04 开设之前（那时历史 Prime 股票池是空的），就会被标出来。
- 有标签的决策日 24 天：约半年的决策日（每 5 个开市日一个，一年约 49 个）。真实数据上 Rank IC 的日间标准差约 0.14，24 天的均值标准误约 0.03，再少就分不清均值和 0 的差别。真实数据默认区间有 184 天；只有一折 60 个开市日的测试段（约 11 个有标签的决策日）会被标出来。

**日期折**。测试区间按开市日切成首尾相接的若干段，每段 `test_sessions` 个开市日（最后一段可短），从早到晚编号。每折的**训练截止**是它测试段第一天的前一个开市日：这折的模型只用到这天收盘为止已知的数据。训练窗是截止日及之前的 `train_sessions` 个开市日；`expanding` 时从日历第一天起，但第一个测试日之前仍要至少有 `train_sessions` 个开市日。历史不够就拒绝，并说明还差几个开市日。

- 按交易日切：同一天的全部证券同在一折，不会一部分在训练、一部分在测试。
- 交易日 `t` 的样本只有在 `t` 不早于训练窗起点、标签结束日 `t+6` 不晚于训练截止时才进训练。所以截止日前最后 6 个开市日的样本不进训练，它们的标签要到测试段才知道。
- 标准化等预处理只在训练折里拟合，不看测试段。
- `t` 之后的行情改变（价格、停牌、退市）和名单变化（某只证券之后离开 Prime）都不改变 `t` 及以前的股票池、特征、分数和逐日决定，各有测试守住。

**特征与标签**（`ohlcv_ratios_v1`）。只用研究价格，只用截至 `t` 收盘的数据，全是没有单位的比值：拆合股以后研究价格会按以后的调整系数重标，绝对价格和成交量会事后改变；成交额是日元，不受拆合股影响，所以它的水平也能用。十个特征：`ret_1`、`ret_5`、`ret_20`、`ret_60`（收盘 ÷ 那么多根日线前的收盘 − 1），`dist_sma20`、`dist_sma60`（收盘 ÷ 均线 − 1），`vol_20`（最近 20 个日对数收益的样本标准差），`range_20`（最近 20 根（最高 − 最低）÷ 收盘的平均），`volume_ratio`（最近 5 根平均成交量 ÷ 最近 20 根的），`log_turnover_20`（最近 20 根平均成交额的对数）。窗口按这只证券有日线的开市日往前数（停牌不算一根，第 5 节），`ret_60` 要 61 根。缺任何一个特征，这一行既不训练也不打分。只训练和打分当天股票池里的证券。

**训练器**（seam，附录 A.6）。`fit` 只拿到一折的训练样本和训练截止，返回模型工件；`predict` 用模型工件给特征表的每一行打分，分数越高越靠前。实验通过构造参数拿到一个「名字和参数 → 训练器」的工厂，测试换成桩，日期折、回放和报告的代码不用改。

- `ridge_v1`：在训练折里算每个特征的均值和标准差做标准化（不变的特征标准差记 1），再拟合 Ridge 回归（scikit-learn，`alpha` 默认 1.0，固定 cholesky 解法）；搜索预算 1，不调参。打分按模型工件里的数值用 numpy 逐个特征累加，同一工件、同一输入的分数逐位相同。
- `rule_short_reversal_v1`：规则基线，不拟合，分数 = −`ret_5`，和 05 短期反转（6.6）的过去收益同口径。
- **模型工件**：每个模型每折一个，JSON：训练器名、参数、拟合结果（`ridge_v1` 是均值、标准差、系数、截距，规则基线为空）、训练截止、样本数，不用 pickle。工件 hash = 训练器名、参数、拟合结果和训练截止的规范 JSON 的 SHA256；读回存下的 JSON 能重算出同一个 hash。

**折外分数与决策日**。每折先训练，再对测试段的每个开市日分别打分，一天调用一次，所以给 `t` 打分时看不到同折里更晚日子的特征。只把**决策日**的分数存下来，带所在折和打分的工件 hash。第一个决策日是测试区间第一天，之后按交易日历每隔 `rebalance_sessions` 个开市日一个决策日，由实验算好、连同分数放进分数表交给策略，策略自己不数开市日。某折训练或打分出错（包括工件里有非有限数）：这折记失败和原因，它的决策日一个分数都没有，其余折照常；不是有限数的分数当作没有分数。

**按分数持仓**（`score_top_n_v1`，6.7）。参数只有 `max_holding_sessions`（默认 0，不限）和 `warmup_sessions`（默认 1）。持仓参与排名（7.2 第 1 步），股票池 Prime 普通股，没有参照行情，不画线。每只当天有可交易日线的证券一条信号：

| 情形 | 空仓 | 持仓 |
|---|---|---|
| 任何一天，已持有 `max_holding_sessions` 天（大于 0 时；开仓成交日算第 1 天，数法同 6.2） | — | 必须清仓，`time_exit` |
| 不是决策日 | 不参与，`not_check_day` | 可持有，`not_check_day`，不带排序值 |
| 决策日，模型没有分数（这天不在分数表里、为空或全是 NaN，例如这折训练失败） | 不参与，`model_unavailable` | 可持有，`model_unavailable`，不带排序值，位置保留 |
| 决策日，这只有分数 | 可持有，`model_rank`，排序值 = 分数 | 可持有，`model_rank`，排序值 = 分数；和候选一起排名，排在 `max_positions` 之外的由组合规则卖出（`ranked_out`） |
| 决策日，模型有分数但这只没有（离开股票池、缺特征） | 不参与，`score_missing` | 必须清仓，`score_missing` |

持有满期优先于其他规则，每天都检查。指标值是 `score`（没有分数为 NaN）和 `check_day`（1 或 0）。分数表里有不是决策日的日子，构造时就报错。不沿用旧分数：模型某个决策日没有分数，就不开新仓，持仓原样保留。组合规则带出来的行为照旧：同分按代码排；卖不出去的持仓（例如跌停开盘）留在账本里，每天重下卖单（7.1 第 4 步），到下一个决策日照样占一个位置。

**读取与回放**。读取起点 = 第一折训练窗起点再往前 61 个开市日（日历开头不够就从日历第一天），这一个起点同时盖住特征、ADV20 和股票池成交额的窗口；读到 `test_to` 为止，之后的行情一概不读，所以测试段最后一两个决策日没有标签，Rank IC 和合格池不计它们。研究输入指纹覆盖读取起点到 `test_to`（ADR-0005 的口径）；区间里有缺股票行情的开市日就失败。

每个回放用同一份行情、同一份股票池和契约里的组合规则、成本，按分数持仓走整段回放 `replay_range`（7.5）：测试首日空仓、无挂单、初始资金起步，`t` 收盘决策、最早 `t+1` 开盘成交，整手、停牌、涨跌停、拆合股、退市、先卖后买、费用和滑点都按本章；运行到 `test_to` 收盘估值，不强平，末日挂单保留但不执行。回放顺序（`position`）：1 是主模型基础成本；2 到 1 + k 是主模型配每个压力场景（滑点 = 基础滑点 + 加成，手续费照旧）；之后是每个规则基线的基础成本，默认共 5 个。每个压力场景都比基础成本贵，没有和基础回放逐笔相同的一档。模型和回放的键（`model`、`baseline_1`……，`base`／`stress`）和页面上的名字（主模型、规则基线 1）都由契约推出（`contract.models()`、`contract.replays()`），报告里每个模型带 `label`、每个回放带 `model_label` 和压力加成 `extra_bps`，页面不从键名里拆名字。

每个回放（压力场景的也一样）每个回放日存一条逐日记录：是否决策日、模型当天有没有分数、所在折、当天股票池和有分数的只数；当天早上每只持仓的处置、理由和分数（当天没有可交易日线的记 `no_signal`）；从空仓角度可持有的候选数；收盘计划的订单和它们最后的结果（成交、过期、放弃或末日挂单）；开盘成交或过期的订单，以及拆合股调整和退市结清；这次计划想要的持仓（收盘持仓 − 计划卖出 + 计划买入）、收盘实际持仓、现金、净值；哪些约束起了作用（放弃的原因、被 ADV20 压缩、排名跌出、排在空位之外的候选）。读取决策日时附上该模型当天分数的前 max(20, 2 × `max_positions`) 名。每天收盘计划了哪些单、开盘生效了什么、哪些单在计划时就被放弃、计划想要的持仓，都由账户模块从回放的账本读出（`Replay.days()`，附录 A.4），实验不自己推算。真实数据默认契约（925 个回放日）五个回放的逐日记录共约 17.3 MB（每个回放 3.1–4.0 MB）；整个实验存下的 JSON 约 31 MB，其中决策日分数 7.8 MB、订单 5.0 MB（2026-10-21 的演示）。

**读取记录**（`data_read`）。库里没有逐行的历史可得时间：日线和上市名册按证券和日期只存一份，后来的修正会覆盖原值（ADR-0001），实验不编造这种时间。每次尝试读完行情就记下：

- `observed_at`：这次读取的墙上时间（UTC），只说明「这次实验什么时候看到这些数据」；
- 四类数据各自的覆盖起止和行数：日线（实验读入的证券和行数，另引研究输入指纹覆盖同一区间全部股票和 TOPIX 的行数）、上市名册与市场分类区间（按哪些开市日定股票池，引指纹里与读取区间重叠的区间段数）、TOPIX（测试区间的收盘个数）、交易日历（读取区间的开市日加测试终点后的下一个开市日，引指纹的行数）；
- 每类数据的可得规则 `available_from`：`t` 日的日线 `t` 收盘后同步，只用于 `t` 收盘及以后的决策、最早 `t+1` 开盘成交；`t` 日的股票池只看那天有效的市场分类区间；TOPIX 只用于基准对比，不进特征；交易日历提前同步，只用来数开市日。

它是运行事实，存在实验记录的 `data_read` 列，不进冻结契约，也不进契约 hash；读取之后才失败的尝试也留着它。详情接口和页面都显示，并写明没有逐行的历史可得时间、只记录本次读取。

**报告**（预测效果和组合效果分开）：

- 基准：TOPIX 价格指数，测试首日收盘到末日收盘，不含分红；合格池等权：每个决策日当天股票池里有标签的证券，标签收益等权平均，逐期连乘，不扣费用、不含分红、不受整手、现金和成交规则约束。合格池等权只供参照，报告和页面都标明它不是可成交的账户；票上「可交易的等权或规则基线」里可交易的那一个是规则基线，它和模型走同一套账本和成交规则。
- 压力场景的口径（`stress_basis`）：每边滑点 = 基础滑点 + 加成，手续费率和最低手续费沿用基础成本、不加压；每个压力回放带它的加成 `extra_bps` 和实际成本。
- 每个回放：7.4 的统计（总收益、年化收益、最大回撤、夏普、胜率、平均持有天数、年化换手），相对 TOPIX 的收益差，成交笔数、费用、期末现金、平均现金占比（各收盘现金 ÷ 净值的平均）、已实现和未实现盈亏；成交率 = 成交 ÷（成交 + 过期），只数买卖单，附过期原因和计划时就放弃的原因计数；订单金额 ÷ ADV20 的中位数、95 分位、最大值和超过上限的笔数（成交金额 ÷ 信号日的 ADV20，买卖单都算）；逐折、逐年的扣费后收益和相对 TOPIX 的差。
- 预测诊断（每个模型，只看决策日）：Rank IC = 当天既有分数又有标签的证券上，分数和标签的秩相关（至少 3 对、两边都有变化才算），给均值和标准差；覆盖率 = 当天有分数的只数 ÷ 当天股票池只数，模型没有分数的决策日记 0；也按折汇总。Rank IC 只是中间诊断，不代替成交后的净值。
- 证据状态：`exploratory`（探索性）或 `insufficient_evidence`（证据不足），列出全部原因：

| 原因码 | 含义 | 证据不足？ |
|---|---|---|
| `history_viewed` | 全部折的测试段登记前已看过 | 否 |
| `history_partly_viewed` | 部分折已看过（列出折号） | 否 |
| `fold_failed` | 某个模型有几折训练或打分失败，每个模型一条 | 是 |
| `too_few_training_samples` | 主模型有几折的训练样本少于最低要求（列出折号和最少的一折） | 是 |
| `coverage_below_minimum` | 主模型决策日平均覆盖率低于最低要求 | 是 |
| `no_prediction_diagnostics` | 主模型没有标签已知的决策日，算不出 Rank IC | 是 |
| `too_few_labelled_days` | 主模型有标签、算得出 Rank IC 的决策日少于最低要求 | 是 |
| `zero_trades` | 主模型基础成本回放零成交 | 是 |
| `too_few_trades` | 主模型基础成本回放成交少于最低要求 | 是 |
| `framework_only` | 没有其他原因时的一条：06a 只验证框架，不出「通过」 | 否 |

**已看过截止日**（`viewed_through`）。登记时取以下几项里最晚的一天冻结进契约：模拟账户已推进到的日期、已完成研究运行（含研究批次的段）的结束日、已完成模型实验的测试终点。测试段第一天不晚于它的折标为「已看过」，只能算探索性：这段历史的结果已经被看到过，重新切分折也造不出盲测。同一区间再登记一次，全部折都是已看过。

**任务与重试**。任务类型 `model_experiment`（第 8 节），和同步、推进、研究共用任务锁，忙时拒绝（409）。和研究运行一样：在任务锁内冻结、校验并持久化后才接受；同一 `request_key` 同一请求返回原实验，参数不同则拒绝；状态 queued／running／completed／failed，进度分阶段（指纹、读取、特征、训练、回放、报告）；整个实验跑完才把折、分数、回放、订单、逐日记录和报告一次写入，中途出错记 failed、原因和失败种类，除指纹和读取记录外什么结果都不留；重启时把未完成的标为失败。失败种类（`error_code`）分四种：`missing_data` 缺数据（测试区间的 TOPIX、测试终点后的日历、或读取区间里某些开市日的股票日线不在库里；原因以「缺数据：」开头，写明哪几天，补齐后可以重试）、`input_changed` 行情已变（重试时指纹和最早一次不同）、`interrupted` 服务中断、`error` 其他错误。登记时就看得出的缺数据（TOPIX、日历）直接 422 拒绝，不留记录；股票日线要到任务里算指纹时才查，所以记成一次失败的尝试。只有失败的实验能重试：重试是一条新记录（`retry_of` 指向原记录），沿用原契约，回放前比对研究输入指纹，和最早一次通过指纹检查的尝试不同就失败，要求登记新实验。因缺数据失败的尝试没有通过指纹检查、不留指纹，补齐数据后的重试不受它约束。

**能审计什么**（ADR-0007）。实验保存冻结契约和 hash、每折的模型工件和 hash、决策日的折外分数、研究输入指纹、读取记录、代码身份（应用源码和依赖锁文件的 SHA256）、每个回放的账本、净值和逐日记录，不保存行情副本。能核对的是这次运行当时算出了什么：工件能重算出 hash；行情没变时，把存下的分数表交给模拟账户推进同一区间，得到逐笔相同的订单和净值（有测试守住）。行情被覆盖以后，不保证重新训练能得到同样的工件，06a 不声称可以重训复现。

**和票面的对应**（ticket 06a，GitHub #10）。下面几处是有意的取舍，不改代码，在这里写明：

- 「冻结预测表经框架与等价手动研究回放产生一致订单／NAV」：手动研究运行（04b，§7.5）只支持技术评级，按分数持仓不在策略注册表里（6.7），研究运行跑不了它。所以测试改用同一套交易规则的模拟账户推进（`Accounts.advance`）对照：把实验存下的分数表交给一个模拟账户推进同一区间，逐条订单和每日净值与实验的主模型基础成本回放相同。研究运行和实验共用 `replay_range`（7.5），研究运行的结果在抽出它前后逐位相同，也有测试守住。
- 持有规则固定为按分数持仓：票面允许 06a 只走 `Disposition`／`priority`。契约声明目标权重、总敞口等尚未实现的指令种类时，登记就拒绝，不会悄悄忽略。训练器只输出一个数，可以是分数，也可以是方向概率或风险估计，按分数持仓只看它的先后。动态权重、择时和风险预算留给 06c 扩展。
- ADV20 上限默认 5%：票面要求冻结「成本／容量」，这个上限就是冻结进契约的容量条件。模拟账户默认不设（7.2 第 4 步），现有账户的行为不变。
- 合格池等权只供参照（见上面的基准），可交易的对照是规则基线。
- 扩展训练窗（`expanding`）、来源账户、规则基线至多 3 个、压力场景至多 5 个：来源账户是验收「来源账户保持不变」需要的，只复制初始资金、组合规则和费用；其余是小的上限和选项，不改变默认契约。

## 8. 后台任务

- FastAPI 一个任务线程、一项待处理槽位；同步／推进／研究／模型实验共用文件锁。忙时立即拒绝（研究和实验 API 返回 409），不承诺多任务排队。queued 仅表示已接受、尚未开始。
- 跨进程互斥：任务开始前取得 `var/job.lock` 文件锁；命令行入口也取这把锁，因此命令行回填与服务里的同步不会同时写库。
- 定时器（按日本时间）：每个开市日 18:00 排入同步；同步报告「当天数据未出」时，30 分钟后再排一次，最晚到 21:00。同步成功后，排入「推进所有 active 账户」。
- 新建账户后立即排入「推进该账户」。
- 研究接受前在任务锁内校验并持久化配置，线程在同一把锁下读数据、执行、写结果。重启仅在能取得锁时标记旧 queued/running 为失败，不误判其他进程的活跃运行。失败重试复制冻结配置并创建新运行，重新记录实际输入，旧结果不覆盖。区间发现、研究批次提交和单段重试各是一个任务，同样在锁内校验并持久化后才接受，忙时拒绝（409）；批次在一个任务里逐段运行，某段失败不影响其他段。重启时一并把 queued/running 的区间发现标为失败。
- 模型实验是第四种研究任务，任务类型 `model_experiment`（§7.7）：登记和重试各是一个任务，在锁内冻结契约、校验并持久化后才接受，忙时拒绝（409）；线程在同一把锁下读数据、训练、回放，跑完才一次写入全部结果。进度按阶段（指纹、读取、特征、训练、回放、报告）写进实验记录，`GET /jobs/current` 也看得到。重启时一并把 queued/running 的实验标为失败；重试是新实验，沿用原契约，回放前比对研究输入指纹。
- 通用任务的即时进度保存在内存；每个任务结束时把结果追加到 `var/jobs.jsonl`。同步与账户推进可在服务重启后重跑；研究另有持久化运行记录，重启后须将中断运行标为失败并注明原因，重试创建新运行，不能丢失已提交的配置或把部分结果当成完成结果。
- 命令行：`python -m app.cli sync`（前台执行同一个同步函数，用于首次回填）、`python -m app.cli advance [--account ID]`。

04b-B API（前缀 `/api/research`，GET 只读，不运行任何东西）：

- `GET /regimes/definition`：分类定义版本、参数、公式文字，以及 TOPIX 行情的起止日（`topix_from`／`topix_through`，供表单默认值；`/data/status` 的最新日期按股票算，不用它）。
- `POST /discoveries`：request_key、search_from、search_to、trend（up／down／neutral）、volatility（high／low／null）；返回 202 + id。同 request_key 同请求返回原 id。
- `GET /discoveries/{id}`：状态、定义、参数、分类指纹、诊断、全部候选区间（含 `sessions_before`：起点之前已有的开市日数，供页面提示策略预热不足）、单批上限、由它发起的批次及其选择记录。
- `POST /batches`：request_key、discovery_id、interval_ids（至少一个）、source_account_id、entry_above、exit_below；返回 202 + id。
- `GET /batches?page=&page_size=`：批次历史；`GET /batches/{id}`：配置、选择记录、逐段状态／进度／尝试／指标、结果分布。
- `POST /batches/{id}/segments/{position}/retry`：新 request_key，只允许最新尝试失败的段；返回 202 + 批次 id 与新运行 id。
- 另加 412：分类所用的 TOPIX 数据自发现后已变化，须重新发现。

06a 模型实验 API（前缀 `/api/experiments`，§7.7；GET 只读存下的结果，不读行情、不训练）：

- `GET /defaults`：登记表的全部默认值、训练器及其默认参数、持有规则能下达和尚未支持的指令种类、任务和特征版本，以及现在登记会冻结的 `viewed_through`。
- `POST ""`：request_key（UUID）、test_from、test_to，其余各项可选（名称、折、决策日间隔、最长持有、训练器及参数、规则基线、来源账户、初始资金／组合规则／费用、ADV20 上限（null = 不设）、压力场景的滑点加成 `stress_bps`（每边 bps，加在基础滑点上）、最低覆盖率、每折最少训练样本、最少有标签的决策日和最少成交数、指令种类）；返回 202 + id。同 request_key 同请求返回原 id，不同请求拒绝。
- `GET ""?page=&page_size=`：历史分页，新的在前，重试也是独立的一条；每条带状态、失败种类、证据状态、测试起止、训练器、基线和契约 hash。
- `GET /{id}`：状态、进度（训练阶段带模型的名字和训练器）、冻结契约及 hash、研究输入指纹、读取记录 `data_read`（读完行情才有）、代码身份、错误和失败种类 `error_code`、`retry_of` 和 `retried_by`、每个模型每折的结果（训练／测试起止、样本数、耗时、模型工件及 hash 或失败原因），完成后还有报告（折及「已看过」标记、各模型的名字 `label` 和预测诊断、基准、压力场景口径、各回放的模型名字、压力加成、指标／逐折／逐年、证据状态和原因、警告、各阶段耗时）。
- `GET /{id}/replays/{position}`：一个回放的成本、每日净值（含现金）、期末持仓、末日挂单、警告和指标；`GET /{id}/replays/{position}/orders?page=&page_size=`：它的账本分页，新的在前。
- `GET /{id}/replays/{position}/days?page=&page_size=&decision_only=`：逐日记录分页，旧的在前；决策日带当天分数前几名；每个回放都有，压力场景的也有。
- `GET /{id}/scores/{model}/{day}`：某个模型（`model`、`baseline_1`……）在某个决策日的全部分数，从高到低，带所在折和工件 hash；不是决策日或那折失败返回 404。
- `POST /{id}/retry`：新 request_key，只允许失败的实验，返回 202 + 新实验 id。
- 404 记录不存在，409 任务忙，422 契约不能运行（中文原因，例如声明了尚未实现的目标权重）。

## 12. 已知局限

- PaperAccount 使用生产日线，J-Quants 后续修正不会回写已成交订单，但会影响新建账户及重新估值。研究保留配置、观察、结果和输入指纹，保证同批比较输入一致；指纹无法恢复已覆盖行情，因此不保证跨数据修正的精确重放（ADR-0001、ADR-0005）。
- 场景分组和阈值比较仍可能受小样本、状态路径差异和反复挑选影响；报告是探索性条件绩效，不自动证明泛化或因果关系。
- 模型实验同样是探索性的：真实库里能当测试段的历史都已经被模拟账户和研究看过，`viewed_through` 会把这些折标成「已看过」，重新切分也造不出盲测。实验只保存分数、工件和结果，行情被覆盖后不保证重新训练得到同样的模型（ADR-0007）。Prime 市场 2022-04-04 才开设，在那之前历史 Prime 股票池是空的，所以训练窗落在这之前的部分没有样本（真实数据上默认契约的第 1 折只有约 10 万个样本，后面各折 13 万到 18 万）。
- 不含分红和税，高股息股的收益被低估（ADR-0003）。
- ETF 分配金同样不入账：1306 每年 7 月落权那天的收益比 TOPIX 低 2.0–2.4%（2022—2026 年各一次），持有 1306 的账户这一天少算这么多。TOPIX 是价格指数，也不含分红，只是它在 3 月、9 月成分股除息时下跌，所以 TOPIX ETF 一直持有账户相对 TOPIX 的超额按整年看接近 0，短期会因两者时点不同而偏离。
- ETF 也按 100 口一手计算；实际売買単位以交易所为准。
- 极端行情时 ETF 的收盘价可能明显偏离 TOPIX（数据里 1348 在 2024-08-05 比 TOPIX 多跌 5.8 个百分点）；账户按 1306 的实际价格成交和估值，这部分差异会留在结果里。
- 只用日线：跟踪止损是「收盘确认、次日开盘卖出」，跳空时按真实开盘价成交，不按止损线成交。
- 开盘即涨停的买单一律视为买不到，现实中可能在收盘按比例分到少量；开盘即跌停的卖单同理。
- 技术评级的长周期 EMA 与 TradingView 页面的数值可能略有差异。
- 同一证券同一交易日，信号页（从当天往前读预热期）和回测中的账户（从起始日往前读，frame 更长）算出的 EMA 类指标不完全相同，偶尔会给出不同的处置——主要是技术评级：EMA200 只往前读 260 天时，当天的值里还有约 55% 来自起点的简单平均，信号页上的入场候选因此可能和回测账户那天的买入对不上。Trend-Pullback 读 180 天，EMA60 里起点只占约 2%，RSI、ATR、ADX 基本不受影响。这是为了让回测只算一次指标而接受的代价（6.2「frame 的起点」）。
- 证券代码被重复使用时只记警告，不拆分两家公司的历史。

## 附录 A：模块 interface

用 Python 伪代码写出每个模块**对外**的全部内容。调用方需要知道的仅限于此；括号里是这个 interface 背后藏着的东西。

### A.1 行情数据模块 `market_data`

```python
class MarketData:
    def __init__(self, session_factory, client: JQuantsClient): ...

    def sync(self, *, until: date | None = None,
             on_progress: Callable[[SyncProgress], None] | None = None) -> SyncReport: ...
    def read(self, codes: Sequence[str] | None, start: date, end: date) -> MarketFrame: ...
    def universe(self, start: date, end: date | None = None, *,          # end 缺省为 start
                 rule: UniverseRule = UniverseRule.PRIME_COMMON_STOCK) -> dict[date, list[str]]: ...
    def instruments(self, *, query: str | None = None,
                    codes: Sequence[str] | None = None) -> list[Instrument]: ...
    def calendar(self) -> Calendar: ...      # sessions()/next()/prev()/offset()，纯内存
    def overview(self) -> DataOverview: ...  # 最大日期、行数、最近任务结果、现算的质量警告

class UniverseRule(StrEnum):   # 股票池规则（6.1）
    PRIME_COMMON_STOCK = "prime_common_stock"; TOPIX_ETF = "topix_etf"

@dataclass(frozen=True)
class Instrument:   code: str; name: str; name_en: str; market: str | None   # 当前市场区分；已退市为 None
```

藏在后面：J-Quants 分页与限速、逐日覆盖写入、市场分类区间的开闭、研究价格的累计系数、质量标记、拆合股核对、每种股票池规则的候选证券与共用的成交额门槛、4 张表的全部 SQL。

`universe` 只带一个参数 `rule`，即股票池规则（6.1），调用方从策略的声明里取来（A.3），有 Prime 普通股和 TOPIX ETF 两种取值。两种规则只在候选证券从哪里来上不同；成交额门槛、20 个开市日的窗口和不可交易的判定是模块内部的常量，两种规则共用同一段计算。它一次给出一段日期里每个开市日的股票池：信号页只问一天，回测要问几百天，逐日调用时每天约 0.25 秒（02 回填数据实测），3 年的回测光股票池就要 3 分钟，一次查询算完整段则只读一次成交额和市场分类区间。`instruments` 给信号页补证券名称与市场、给 `GET /api/instruments?q=` 做搜索（按代码前缀或名称包含）；只有这个模块能读 `instruments` 表，所以由它提供。

`MarketFrame` 是一个很薄的包装：内部是以 (证券, 交易日) 为索引的 DataFrame，列名由模块给出的常量声明（研究价格 OHLCV、成交价格 OHLC、成交额、涨跌停标志、质量标记、调整系数、除权类型），另带 `listed_through`（证券代码 → 它在名册中的最后一个交易日，仍在名册中为 `None`，由市场分类区间推出），并提供宽表访问器 `wide(列名)`（行是交易日、列是证券代码，没有日线的格子为 NaN），指标模块直接吃这种宽表。它是 interface 的一部分，列名和空值语义都要写进文档——这是选择用 pandas 换来的代价。调整系数、除权类型和 `listed_through` 是给模拟账户的——拆合股调整和退市结清（7.1）要用，而账户模块不能直接查这四张表；回测时账户按「那一天」判断在不在名册，不能用 `instruments` 给出的当前市场区分。

`client` 从构造函数传入，这就是 J-Quants seam：生产用 HTTP 适配器，测试用内存假适配器。

**删除测试**：删掉它，累计系数、质量判定、日历对齐和 4 张表的 SQL 会散到策略、账户、API 和命令行里。复杂度是被它集中住的。

```python
Prices = Series | DataFrame   # 一只证券，或宽表（行是交易日、列是证券代码）
```

### A.3 策略 seam `strategies`

```python
class Strategy(Protocol):
    name: str
    warmup_sessions: int
    plots: tuple[Plot, ...]          # 图上画哪些指标：指标名 → 叠在价格上，还是单独一栏
    universe_rule: UniverseRule      # 在哪套股票池里新开仓（6.1）；不声明的取 Prime 普通股
    reference_series: tuple[str, ...]  # 读取但不交易的行情代码，例如 TOPIX（6.2）；不声明的为空

    def evaluate(self, frame: MarketFrame, day: date,
                 holdings: Sequence[Holding]) -> list[Signal]: ...

def build_strategy(name: str, params: Mapping[str, Any]) -> Strategy: ...
STRATEGY_DEFAULTS: Mapping[str, Mapping[str, Any]]   # 供新建账户页展示
def strategy_infos() -> list[StrategyInfo]: ...      # 名称、默认参数、股票池规则、warmup_follows，不必建策略
def codes_to_read(strategy: Strategy, codes: Iterable[str]) -> list[str]: ...  # codes ∪ 参照行情，读行情的调用方都用它

def entry_candidates(market: MarketData, strategy: Strategy, day: date) -> list[Candidate]: ...
def history(market: MarketData, strategy: Strategy, code: str,
            start: date, end: date) -> SecurityHistory: ...

@dataclass(frozen=True)
class Holding:      code: str; quantity: int; opened_on: date
@dataclass(frozen=True)
class Signal:       code: str; disposition: Disposition; reason_codes: tuple[str, ...]
                    indicators: Mapping[str, float]; priority: float | None
@dataclass(frozen=True)
class Plot:         indicator: str; pane: Literal["price", "separate"]
@dataclass(frozen=True)
class Candidate:    signal: Signal; instrument: Instrument          # 已按排序值降序、代码升序
@dataclass(frozen=True)
class SecurityHistory:
                    frame: MarketFrame                              # 研究价格与成交量
                    indicators: DataFrame                           # 行是交易日、列是 plots 里的指标
                    entries: list[date]                             # 未持仓角度得到「可持有」的交易日
```

只有一个方法：`frame` 里每只能判断的证券都得到一条信号（含「不参与」，带当天指标值）；`holdings` 传空，其中「可持有」的就是入场候选；传账户持仓，就同时得到该账户的清仓信号。参数在构造时就固定在策略对象里，不出现在方法签名上。指标对整个 `frame` 只算一次、按 `frame` 缓存，缓存不属于 interface（6.2「frame 的起点」）。股票池规则和参照行情跟 `warmup_sessions`、`plots` 一样是声明：策略自己仍不筛股票池、不查数据库，调用方按股票池规则取股票池（`entry_candidates`、模拟账户推进、研究运行），并把参照行情加进读取范围（`entry_candidates`、`history`、模拟账户推进、研究运行，都经由 `codes_to_read`）。参照行情的代码只是输入，`evaluate` 永远不给它信号。

策略类还可以声明 `warmup_follows: WarmupFollows | None`（参数名和多出的个数）：预热期至少是这个参数加上这个数，TOPIX 均线为 `ma_sessions` + 0，TOPIX 动量为 `lookback_sessions` + 1，其余为空。策略自己的校验和新建账户页都按它，规则只写一处。

五个适配器：Trend-Pullback v1 和技术评级 v1（股票池规则取默认的 Prime 普通股，没有参照行情），TOPIX ETF 一直持有 v1（TOPIX ETF，没有参照行情），TOPIX 均线 v1 和 TOPIX 动量 v1（TOPIX ETF，参照行情 TOPIX）；后三个见 6.5。规则只读参照行情的这两个策略共用基类 `ReferenceSeriesStrategy`（6.2）。05 的三个候选（6.6）也在注册表里，股票池规则都是 Prime 普通股，没有参照行情。

```python
@dataclass(frozen=True)
class ScoreTable:   decision_days: frozenset[date]                  # 调用方按交易日历算好的决策日
                    scores: Mapping[date, Mapping[str, float]]      # 决策日 → {代码: 分数}；不是决策日的日子构造时报错

```

按分数持仓 `ScoreTopN`（6.7、§7.7）是 seam 的另一个适配器，但分数要从外面给，所以不进注册表（`build_strategy`、`STRATEGY_DEFAULTS`、`strategy_infos()` 里都没有它），由模型实验直接构造。

`entry_candidates` 和 `history` 不是 seam，是写在 seam 之上的两个普通函数：它们藏住「按策略声明的股票池规则取股票池、连同参照行情从第一个评价日往前读预热期那么多个开市日、调用 `evaluate`、补上证券名称」这套组装。入场候选只取股票池里的证券；`history` 交回的行情只有该证券自己的。`history` 按日循环调用同一个 `evaluate`，从每天的信号里收集指标曲线和入场点，不为画图另加方法。**删除测试**：删掉它们，「预热期决定往前读多远」会同时出现在信号页和证券详情页两个 API 处理函数里，而 A.7 规定 API 里不写业务规则。账户模块读的是覆盖整段回测的长 `frame`，不经过它们，直接调用 `evaluate`。

**删除测试**：删掉这个 seam，入场和退出规则会长进账户推进的循环里，信号页也就没法在不建账户的情况下显示候选。

另有一个普通函数 `strategy_choices()`：把每个策略的声明（`strategy_infos()`）和账户这边的结论配在一起——股票池规则点名的代码、建议的组合规则——供 `GET /strategies` 转成 JSON（第 9 节），API 里因此不写这层配对。

`advance` 是模拟账户推进的入口：拆合股调整、退市结清、开盘成交、卖单重下、出信号、组合规则、写订单，全在它后面。它从 `advanced_through` 的下一个开市日推进到 `through`（默认最新交易日）；重复调用不会重复推进。paper account 的历史追赶和后续模拟交易都使用它；04b 增加独立研究入口，复用这些规则而不写 paper 账本（ADR-0006）。

`advance` 自己只做读库、写库和逐日循环：一次读出整段所需的行情（`MarketData.read` 取整段股票池的并集加上持仓、挂单和策略的参照行情）和整段股票池（`MarketData.universe(start, end, rule=策略声明的股票池规则)`），然后每个交易日分开盘、收盘两段——收盘段要先拿到开盘成交之后的持仓，才能问策略 `evaluate(frame, t, holdings)`。

内部的 seam 只给自己的测试用，不对外；全部不碰数据库、不产生副作用，所以「开盘涨停买不到」「卖出所得当场可用」「现金不够减手数」「十合一的零股折现」这类规则可以用几行合成数据测，而不必造一个账户再推进一年：

```python

                                                                  # adv20 只在 rules 设了 ADV20 上限时才用
```

`day` 是账户看到的 `t` 日行情：当天的成交价格、涨跌停标志、质量标记、调整系数与除权类型，前一交易日收盘成交价格，以及哪些证券已不在名册中。`plan_orders` 收到的是 `advance` 过滤好的信号：`exits` 是持仓（未重下卖单的）得到的判断，`candidates` 是当天在股票池内、未持仓、「可持有」的入场候选；`closes` 是 `t` 日收盘成交价格，用来算计划股数和预估卖出所得。

**删除测试**：删掉 `Ledger`，「持仓、现金由订单记录推出」会在 `advance` 和 `report` 里各写一份，迟早不一致；把 `open_session` 拆回逐单的 `fill`，先卖后买与现金流转就只能经由 `advance` 测。

04b 的研究能力由账户模块提供提交配置、执行比较、读取状态/报告和逐日观察的公开入口，签名随实现确定；调用方不读取内部表或直接拼装 `Ledger`、`plan_orders`、`open_session`。研究记录、调度和报告可独立组织，交易规则仍由账户模块内的共享实现负责。

### A.6 模型实验模块 `experiments`（06a）

```python

FEATURES_V1 = "ohlcv_ratios_v1"; FEATURE_NAMES: tuple[str, ...]; HORIZON = 5
def label_sessions(horizon=HORIZON) -> int                           # 标签结束日离交易日几个开市日，= horizon + 1
def feature_table(frame: MarketFrame, days) -> DataFrame             # 索引 (as_of, code)；缺特征的行不出现
```

**训练器 seam**：`fit` 只拿到一折的训练样本和截止日，`predict` 一次只拿到一个交易日的特征，所以训练器既看不到测试段的标签，也看不到同折里更晚日子的特征。两个真实适配器 `ridge_v1` 和 `rule_short_reversal_v1`；训练器从 `trainers` 工厂按契约里的名字和参数建出来，测试传入桩工厂。**删除测试**：删掉这个 seam，Ridge 的拟合和打分会长进折外循环和实验任务里，换一种模型就要改切分、回放和报告的代码，06b、06c 也就没法沿用同一条证据路径。

**删除测试**（整个模块）：删掉它，「训练样本的标签不能越过训练截止」「只保留决策日的分数」「压力场景只在基础滑点上加成」「已看过的折只能算探索性」会散进 API 处理函数和账户模块的研究代码里，而账户模块只该管交易规则。
