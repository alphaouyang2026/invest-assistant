# 04b-A — 指定区间运行策略，在页面查看结果

**状态：** ready-for-agent。
**依赖：** 现有 04 模拟账户基线；不依赖旧 04b-00–08 或市场分类。
**父任务：** [04b](04b-research-backtest-account-ui.md)。

## 用户可见的交付

从技术评级账户点击“回测此策略”，打开 `/accounts/research`：

1. 确认策略 `technical_rating_v1`、来源账户初始资金／组合规则／费用。
2. 手动选择开始和结束日期，设置一组入场／退出阈值。
3. 点击运行，看到排队、进度或明确失败原因。
4. 完成后看到实际区间、策略与配置、净收益、同期 TOPIX、收益差、最大回撤、成交数、费用、净值／回撤图、交易记录及期末持仓。
5. 刷新仍能看到本次结果；修改日期或参数再运行会创建新记录。

这一步必须能独立使用，不以只有迁移、接口或 mock 页面作为完成。

## 实现检查项（都在本 ticket 内完成）

- [ ] 按当前基线定义最小请求／响应与运行记录，同步 spec、ADR-0005/0006 及直接冲突的术语。只定义本步所需契约，不要求先设计完所有高级研究模式。
- [ ] 账户入口与页面表单：策略本期只有 technical_rating；阈值默认 0.5 / -0.1、步长 0.1，服务端验证有限数值与 [-1,1]。保留普通账户其他策略不变。
- [ ] 起止日期必须为已有日历中的开市日，起点≤终点；非法或缺少预热时返回可理解错误，不静默更改。单日范围可运行，显示零成交及原因。
- [ ] 冻结来源身份和初始配置，以手选起点为空仓起点。保存独立研究运行、订单／成交、日 NAV、实际数据覆盖／内容指纹、代码版本和错误；不写 paper 账本，不复制当前持仓。
- [ ] 复用账户逐日规则；必要抽取共享代码，不要求大型引擎框架。保留公司行动、整手、停牌／涨跌停、费用、名额／现金约束。
- [ ] 预热只准备指标；s 收盘产生信号、最早 s 后首个交易日开盘成交；末日 e 收盘估值，不执行 e 后订单，不虚构强平。记录期末持仓、未实现盈亏和未执行订单。
- [ ] POST 异步提交并返回持久 ID，复用单写者队列／锁；GET 只查询结果。状态包括排队／运行／完成／失败，重启标记中断，显式重试新建尝试并保留旧结果；防止重复点击造成无意重复提交。
- [ ] 运行读取一致输入；相同内容同指纹，价格修正即使行数不变也能识别。来源账户后来修改／删除不影响已保存结果，历史研究不随日常同步继续推进。
- [ ] 报告以 s 收盘至 e 收盘为共同口径：NAV 和 TOPIX 归一图、总收益及收益差、最大回撤、成交数、实际费用；期末按市值估值并区分已实现／未实现。无交易／无平仓指标不伪造，短段不靠年化或 Sharpe 排名。
- [ ] 页面具备加载／失败／空记录／刷新恢复，交易列表分页，轮询卸载停止；使用生成的 API 客户端。明确不含分红／税等现有口径、结果为探索性。

不要求本步保存所有未下单候选；实际订单／成交理由沿用现有规则，不能为减少范围丢失成交账本的可追溯性。

## 演示与验收（本步完成即执行）

- [ ] 在页面选定一个有数据与预热的区间，使用默认参数运行；展示真实净值、基准、回撤和交易记录，而非占位数字。
- [ ] 同区间换一组阈值再运行，可分别查看两次结果；无须提供并排参数比较工作台。
- [ ] 合成数据手算收益、费用和期末未平仓估值；与相同初始条件的 paper 回放核对逐日订单、现金、NAV，验证无交易规则漂移。
- [ ] 验证预热无交易、首日不能开盘成交、单日段、末日不越界、来源账户前后不变。
- [ ] API／前端测试覆盖成功、日期／参数错误、失败重试与刷新恢复，现有账户测试通过。
- [ ] 写简短验收记录：实际数据区间、参数、命令／测试结果、页面操作和耗时。没有可用真实数据时明确未完成的演示，不虚称已可用。
