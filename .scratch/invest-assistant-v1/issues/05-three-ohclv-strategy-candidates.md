# 05 — 三类 OHLCV 策略候选研究

**What to build:** 在可复现的研究回测流程中加入长趋势 / 绝对动量、短期反转、横截面 6-1 / 12-1 动量三类候选策略。先评估可行性和样本外表现；未通过预先声明的门槛前，不接入日常 paper account，也不晋级为 champion。

**Design:** [策略扩展、精细回测与策略选定方案](../../strategy-backtesting-selection-research.md) §3、§5、§6、§9；[invest-assistant v1 系统设计](../spec.md) §6–§8

**Blocked by:** [04b — 账户页面：固定区间策略研究回测](04b-research-backtest-account-ui.md)。04b 先用现有 `trend_pullback_v1` 与 `technical_rating_v1` 打通研究运行、复现和报告；05 再在同一页面和 SimulationEngine 中加入三个候选策略及月度再平衡。

**Status:** ready-for-agent

## 研究范围

- [ ] 三类策略均只使用当时可见的日频 OHLCV / 成交额字段；不接入财务因子，不使用未来数据
- [ ] 每个策略家族先登记一个主版本和至多一个变体；冻结规则、股票池、交易时点、allocator、退出规则、成本情景、训练 / 验证 / 盲测区间及主要指标后再查看相应 OOS 结果
- [ ] 每个版本使用独立且递增的策略版本号；规则或参数在查看结果后发生变化时创建新版本，保留原 run 和失败结果
- [ ] 研究期间保持原有 `technical_rating_v1` 与 `trend_pullback_v1` 不变，作为诊断基线；不能通过反复调整候选参数追逐最高全样本 Sharpe
- [ ] 所有入场信号使用 t 日收盘后可得数据，最早在 t+1 开盘成交；月度策略在预先定义的月末检查并于下一可交易开盘执行

## 候选策略定义

### A. 长趋势 / 绝对动量

- [ ] 主版本 `long_trend_sma200_v1`：每月末检查，收盘价高于 SMA200 时纳入候选，否则不持有；以月度频率维护目标持仓
- [ ] 预注册变体 `absolute_momentum_12m_v1`：每月末检查，过去 12 个月收益为正时纳入候选，否则不持有；12 个月窗口按 252 个交易日定义
- [ ] 对缺少完整预热数据、停牌、无可成交开盘价的证券采用统一的不可交易处理规则，不用缺失值推断为正向信号
- [ ] 报告震荡区间反复进出、市场暴露、持有期、换手及成本后表现

### B. 短期反转

- [ ] 主版本 `short_reversal_5d_v1`：在合格股票池中按过去 5 个交易日收益由低到高排序，选择事先固定的弱势分位数组合；流动性过滤后持有 5 个交易日
- [ ] 预注册变体 `short_reversal_20d_v1`：同样流程，但排序窗口为过去 20 个交易日、目标持有期为 10 个交易日
- [ ] 在实验 spec 中冻结弱势分位、最低流动性条件、持仓数量、退出 / 换仓规则；不得看过 OOS 后再选择分位或筛选门槛
- [ ] 记录换手率、成交率、订单占 ADV20 比例、成本前后收益，以及 10 / 25 / 50 bps 单边成本压力结果

### C. 横截面 6-1 / 12-1 动量

- [ ] 主版本 `cross_sectional_momentum_6_1_v1`：每月末以过去 126 个交易日收益排序，跳过最近 21 个交易日；按冻结的横截面规则选择目标证券并月度再平衡
- [ ] 预注册变体 `cross_sectional_momentum_12_1_v1`：窗口改为过去 252 个交易日，仍跳过最近 21 个交易日；其他股票池、选择规则和 allocator 与主版本相同
- [ ] 仅使用当日合格股票池和当时可见历史；历史长度不足的证券不得参与排序
- [ ] 与同一股票池月度等权、TOPIX 和 `technical_rating_v1` 比较，分开报告市场收益、选股收益、换手和成本影响

## 组合、基准与执行约束

- [ ] 月度策略使用固定且相同的 PeriodicTopN / 等权 allocator；策略只输出信号与目标排序，不直接决定股数
- [ ] 保留 1/N / 股票池等权为组合构建基线；逆波动权重只能作为另行预注册的后续 challenger
- [ ] 使用同一 Execution Model 比较所有候选，至少报告现有简化成本和每边 10 / 25 / 50 bps 成本情景
- [ ] 设置并报告单日订单 ADV20 占比上限；超限时按预先固定的部分成交或整单拒绝规则模拟
- [ ] 报告 TOPIX、合格股票池等权、现有技术评级策略三类基准；总收益标明不含现金分红和税（如当前数据 / 账本仍未覆盖）

## 评估与晋级

- [ ] 开发期、验证期和最近一年盲测期预先固定；盲测只在版本冻结后运行一次，允许读取 warm-up 数据但不把 warm-up 收益计入测试
- [ ] 先检查因果、数据质量、覆盖证券数、最低交易数和成交可行性；证据不足标为 `insufficient_evidence`，不得算通过
- [ ] 逐年、逐 fold 报告净超额收益、年化收益 / 波动、Sharpe / Sortino、最大回撤、持有期、换手、成交率、容量及成本分解
- [ ] 完成参数邻域、成本、延迟一天成交、异常大额交易剔除等稳健性检查；保留全部 run、变体和淘汰原因
- [ ] 只有通过 OOS 硬门槛的版本才可进入 paper challenger；按 Pareto 表现、稳定性、成本 / 容量、与现有 champion 的相关性、复杂度和可解释性评估
- [ ] 晋级由人工确认；不得因单月表现落后自动替换 champion

## 完成条件

- [ ] 三个策略家族及预注册变体均可由同一 SimulationEngine 运行，且结果绑定策略版本、参数、代码 commit、数据 manifest、区间、基准、allocator 和 execution / cost model
- [ ] 相同 manifest 与 spec 可复现相同的信号、订单、成交、净值和指标；t 日信号不受 t 日之后数据影响
- [ ] 每个候选都有可审阅的研究报告，明确标注通过、失败或证据不足及对应原因；本 issue 完成不代表任一策略已经有效或获得投资推荐
